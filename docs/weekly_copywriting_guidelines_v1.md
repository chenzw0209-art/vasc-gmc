# 周报文案整理规范 V1.0

## 1. 定位

周报服务对象是销售，页面目标不是写行业报告，也不是做 CRM 管理后台。

周报只回答这些问题：

- 本周该看哪些客户
- 为什么现在值得看
- 客户属于什么行业
- 有哪些公开增长信号
- 还有哪些同类客户可一起扫盘
- 本周/下周是否有展会窗口

## 2. 总原则

所有字段都应像表格单元格，而不是报告段落。

要求：

- 短句优先
- 事实优先
- 销售可扫读优先
- 一个字段只表达一个意思
- 避免解释链过长
- 避免把来源、判断、备注混在同一字段

## 3. 禁止出现的内容

周报内容中不要出现以下词或字段：

- BD
- CRM
- 跟进中
- 待分配
- 已转商机
- 商机状态
- 负责人
- 下一步动作
- 推荐分
- 机会指数
- 星级
- AI推荐
- 客户评分
- 内部备注
- 获客目标

建议替换为：

- 重点关注
- 公开信号
- 信源质量
- 行业扫盘
- 同类客户
- 展会窗口
- 增长信号

## 4. 字数预算

| 字段 | 建议长度 |
|---|---:|
| 品牌/企业 | ≤ 24 个英文字符 / ≤ 16 个中文字符 |
| 主营品类 | ≤ 12 个中文字符 |
| 事件类型 | ≤ 6 个中文字符 |
| 事件摘要 | ≤ 60 个中文字符 |
| 本周摘要 | ≤ 90 个中文字符 |
| 行业信号单条 | ≤ 45 个中文字符 |
| 同类客户事件 | ≤ 45 个中文字符 |
| 展会名称 | ≤ 20 个中文字符 |
| 地点 | ≤ 8 个中文字符 |

## 5. 品牌/企业名称

要求：

- 优先使用品牌名
- 不使用完整工商主体
- 中英文品牌只保留一个主名
- 不在品牌字段里写品牌组合、业务说明或来源说明

推荐：

```text
Anker
DJI
Roborock
Laifen
TESSAN
```

不推荐：

```text
Anker Innovations Technology Co., Ltd. 及其子品牌组合
```

## 6. 主营品类

要求：

- 使用名词短语
- 最多 12 个中文字符
- 不写解释句
- 不写“未在底表中找到”
- 不写来源判断过程

推荐：

```text
充电配件
扫地机器人
智能摄像头
便携储能
美发工具
录音麦克风
空气炸锅
智能戒指
```

不推荐：

```text
未在3C底表中找到，但可通过公开资料判断其属于消费电子相关方向
```

## 7. 事件类型

事件类型保持短标签，不要写成长句。

推荐枚举：

```text
新品发布
PR活动
渠道动作
展会
招投标
行业政策
```

不推荐：

```text
该品牌近期可能存在新品、渠道、PR等多种综合性动态
```

## 8. 事件摘要

要求：

- 一句话
- 40-60 字以内
- 只写事实
- 结构为“谁 + 做了什么 + 为什么值得看”
- 不堆链接、来源、内部备注

推荐：

```text
Anker在CES展示充电、智能家居与娱乐设备组合，验证新品窗口。
```

```text
DJI发布创作者设备相关新品，影像工具链仍有更新节奏。
```

不推荐：

```text
根据PRNewswire以及多个公开来源显示，该企业可能在近期有值得持续关注的业务变化，后续建议结合销售策略进一步判断。
```

## 9. 本周摘要

要求：

- 1 段
- 60-90 字
- 销售视角
- 包含行业方向、客户方向、信号类型

模板：

```text
W23建议优先关注【行业方向】，重点客户集中在【国家/平台】，多品牌出现【新品/渠道/展会/PR】信号，可用于本周客户扫盘。
```

示例：

```text
W23建议优先关注手机配件与智能硬件方向，重点客户集中在美国站，多品牌出现新品发布、渠道扩张和展会信号。
```

## 10. 行业扫盘文案

行业扫盘只做销售摘要，不做完整行业研究。

推荐字段：

```text
行业GMV：$1.23B
增长：+8.2%
CN占比：35.6%
Top中国玩家：Anker
增长信号：CES新品、渠道扩张、Amazon/TikTok承接
```

不推荐：

```text
该行业长期来看具备较大潜力，考虑到宏观消费趋势、供应链结构、品牌竞争格局和平台变化，建议持续深入研究。
```

## 11. 同类客户文案

要求：

- 来自规则匹配，不写 AI 推荐
- 不展示推荐分
- 不展示机会指数
- 不展示星级
- 每个客户只保留最近一条公开信号

字段格式：

```text
品牌/企业 | 国家 | 主营品类 | 最近事件 | 事件时间 | 信源质量
```

最近事件建议 30-45 字以内。

## 12. 展会文案

要求：

- 日期前置
- 展会名称短
- 地点短
- 行业只写一个主行业
- 不写获客目标
- 不写负责人
- 不写内部备注

推荐：

```text
2026-06-09 | 光亚展 | 广州 | 照明设备
```

不推荐：

```text
该展会建议BD重点关注，适合安排客户拜访，后续可分配给华南团队跟进。
```

## 13. 推荐输入字段格式

后续整理底表或分析表时，建议使用以下字段：

```text
品牌：Anker
国家：US
一级行业：Consumer Tech
二级行业：手机配件/电源充电
主营品类：充电配件
事件时间：2026-01-06
事件类型：新品发布
事件摘要：Anker在CES展示充电、智能家居与娱乐设备组合。
信源质量：A
```

## 14. 质量自检清单

提交周报内容前，逐条检查：

- 品牌名是否短且可读
- 主营品类是否是名词短语
- 事件摘要是否不超过 60 字
- 是否去掉了 BD/CRM/跟进/分配/商机等内部管理词
- 是否没有推荐分、机会指数、星级
- 展会是否日期前置
- 行业扫盘是否只保留销售摘要
- 同类客户是否来自规则匹配，而不是主观推荐

## 15. 页面挤压责任规则

周报内容可以保留完整证据链，但首屏只能展示短字段。

内容层负责提供：

```text
本周摘要短版
客户动态摘要短版
建议关注点短版
展会窗口价值短版
证据链详情
```

可视化层必须执行：

1. 主表只展示短文案字段。
2. 证据链、URL、复核备注进入详情面板。
3. 卡片超出高度时减少展示条数。
4. 表格超出宽度时删除次要列。
5. 禁止缩小字号硬塞。
6. 禁止横向滚动主表。
7. 禁止把详情字段放进主表。
8. 禁止把多个信息组切成三栏小字墙。

如果在 1440×900 屏幕下出现字段互相挤压、文字大量截断、模块高度撑爆或卡片内小字堆叠，默认判定为可视化层未正确降级展示。

详细规则见：

```text
docs/visualization_overflow_guardrails_v1.md
```
