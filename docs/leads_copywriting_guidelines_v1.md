# 线索模块文案整理规范 V1.0

## 1. 定位

线索模块是市场情报线索池，不是 CRM，不是销售跟进后台。

它只回答：

- 最近有哪些公开可验证信号
- 信号属于什么类型
- 对应哪个品牌/企业
- 属于什么国家、行业、品类
- 信源质量如何
- 该信号能否进入周报或行业扫盘

## 2. 总原则

线索文案应像结构化情报记录，而不是跟进备注。

要求：

- 每条线索只表达一个事件
- 字段短、准、可扫读
- 优先事实，不写销售动作
- 不混入负责人、状态流转、分配信息
- 不用夸张判断词
- 不把长新闻原文塞进摘要

## 3. 禁止出现的内容

线索模块不要出现以下词或字段：

- BD
- CRM
- 跟进人
- 跟进状态
- 待分配
- 已分配
- 已转商机
- 商机阶段
- 交付大区
- 下一步动作
- 联系方式
- 客户备注
- 内部备注
- 推荐分
- 机会指数
- 星级
- AI推荐

建议替换为：

- 信号类型
- 事件类型
- 事件摘要
- 信源质量
- 证据链
- 关联行业
- 关联品牌
- 公开来源

## 4. 字数预算

| 字段 | 建议长度 |
|---|---:|
| 品牌/企业 | ≤ 24 个英文字符 / ≤ 16 个中文字符 |
| 国家/地区 | ≤ 8 个字符 |
| 一级行业 | ≤ 18 个字符 |
| 二级行业 | ≤ 16 个中文字符 |
| 主营品类 | ≤ 12 个中文字符 |
| 信号类型 | ≤ 6 个中文字符 |
| 事件类型 | ≤ 6 个中文字符 |
| 事件摘要 | ≤ 70 个中文字符 |
| 证据摘要 | ≤ 80 个中文字符 |
| 来源名称 | ≤ 20 个中文字符 |

## 5. 信号类型

信号类型用于判断线索归属。

推荐枚举：

```text
客户动态
展会动态
招投标动态
行业政策
```

不要写成：

```text
这是一个可能值得销售团队后续关注的综合型客户线索
```

## 6. 事件类型

事件类型用于描述发生了什么。

推荐枚举：

```text
新品发布
PR活动
渠道动作
展会
招投标
行业政策
市场报告
其他
```

要求：

- 使用固定短标签
- 不要把事件类型写成一句话
- 不要把多个事件类型堆在一个字段里

## 7. 品牌/企业名称

要求：

- 优先品牌名
- 不写完整公司主体
- 不写品牌组合说明
- 不写来源名称

推荐：

```text
Anker
DJI
Roborock
Laifen
TESSAN
```

不推荐：

```text
Anker Innovations及其旗下Anker/eufy/Soundcore多个品牌组合
```

## 8. 主营品类

要求：

- 使用短名词
- 不写底表备注
- 不写“未找到”
- 不写推理过程

推荐：

```text
充电配件
智能安防
扫地机器人
便携储能
美发工具
智能穿戴
```

不推荐：

```text
该企业主营品类未能在当前底表中完全匹配，但从公开信息看属于消费电子相关产品
```

## 9. 事件摘要

要求：

- 一句话
- 50-70 字以内
- 写清楚“谁 + 做了什么 + 公开信号价值”
- 不写内部判断
- 不写销售动作

推荐：

```text
Anker在CES展示充电、智能家居与娱乐设备组合，形成新品与展会双重信号。
```

```text
DJI发布创作者设备相关新品，影像工具链保持更新节奏。
```

不推荐：

```text
该客户建议后续由BD重点跟进，可考虑进入商机池并安排销售动作。
```

## 10. 证据摘要

证据摘要用于说明为什么这条线索可信。

要求：

- 只写公开证据
- 不写主观判断
- 不超过 80 字
- 能说明来源类型即可

推荐：

```text
来源为品牌官方新闻稿，包含发布时间、产品名称和发布场景。
```

```text
来源为展会官网，记录包含展会时间、地点和参展主题。
```

## 11. 信源质量

推荐枚举：

```text
A
B
C
待判断
```

解释：

- A：官方来源、权威媒体、可交叉验证
- B：行业媒体、公开平台、信息较完整
- C：单一来源或字段不完整
- 待判断：缺少关键字段，需后续补证据

不要写：

```text
高质量客户
强推荐客户
重点必打客户
```

## 12. 线索详情文案

线索详情建议分四块：

```text
事件摘要
市场相关性
证据链
原始记录
```

每块要求：

- 标题固定
- 内容不超过 120 字
- 不写内部跟进
- 不写销售责任人

## 13. 推荐输入字段格式

```text
信号类型：客户动态
品牌/企业：Anker
国家/地区：US
一级行业：Consumer Tech
二级行业：手机配件/电源充电
主营品类：充电配件
事件时间：2026-01-06
事件类型：新品发布
事件摘要：Anker在CES展示充电、智能家居与娱乐设备组合。
信源质量：A
来源名称：PRNewswire
来源链接：https://...
证据摘要：品牌官方新闻稿，包含产品组合和展会发布时间。
```

## 14. 质量自检清单

- 是否是一条公开事件，而不是销售动作
- 是否没有 BD/CRM/跟进/分配/商机字段
- 品牌名是否短且可读
- 主营品类是否是短名词
- 事件类型是否来自固定枚举
- 事件摘要是否不超过 70 字
- 信源质量是否为 A/B/C/待判断
- 是否保留来源链接或来源名称

## 15. 页面挤压责任规则

线索模块以主列表扫读为第一优先级，不把完整情报记录塞进列表。

内容层负责提供：

```text
主列表短字段
动态摘要短版
建议关注点短版
证据摘要
原始信源链接
详情长文案
```

可视化层必须执行：

1. 主列表只展示短字段。
2. URL、证据链、复核备注只进入详情面板。
3. 长文案只能进入详情或 tooltip。
4. 容器超出高度时减少展示行数。
5. 表格超出宽度时删除次要列。
6. 禁止缩小字号硬塞。
7. 禁止横向滚动主表。
8. 禁止把多个信息组切成三栏小字墙。

如果内容层已经提供短字段和详情字段，而页面仍然挤压，默认判定为可视化层未正确降级展示。
