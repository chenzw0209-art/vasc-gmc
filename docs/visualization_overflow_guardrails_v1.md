# 可视化防挤压与字段降级规则 V1.0

## 1. 责任边界

页面挤压不是单纯的内容长度问题。内容层可以提供完整信息，但页面层只能展示该展示的部分。

默认判定：

```text
如果页面发生字段互相挤压、文字大量截断、模块高度撑爆、卡片内小字堆叠，优先判定为可视化层未正确执行降级展示。
```

内容 Agent 负责：

1. 主表短文案
2. 卡片短文案
3. 详情长文案
4. 原始证据链

可视化 Agent 负责：

1. 只展示短文案字段
2. 长文案进入详情面板或 tooltip
3. 字段超限时自动降级展示
4. 容器超限时减少展示行数
5. 宽度不足时删除次要列
6. 保持模块边界、字号和间距稳定

## 2. 主表展示规则

主表只放高频扫读字段。

允许进入主表：

```text
应用/商品名称
归属方
线索类型
一级行业/二级行业
目标市场/渠道
动态类型
动态日期
动态摘要短版
建议关注点短版
信源等级
是否建议入库
```

不得进入主表：

```text
完整 URL
证据原文
复核备注
规则解释
详情长文案
多个信源的完整说明
内部管理字段
```

主表字段降级顺序：

1. 先隐藏来源名称、入库判断等次要列
2. 再隐藏目标市场/渠道
3. 再隐藏建议关注点
4. 保留应用/商品名称、归属方、行业、动态类型、日期、摘要、信源等级

禁止通过缩小字号硬塞字段。

## 3. 卡片展示规则

卡片只显示一屏内能读完的短信息。

卡片内容超出时按顺序降级：

1. 减少展示条数
2. 隐藏辅助说明
3. 将长句转入详情面板
4. 保留标题、核心数字、1-2 条短事实

禁止：

- 把详情字段放进卡片
- 把多个信息组切成三栏小字墙
- 让卡片靠缩小字号容纳更多内容
- 用横向滚动解决卡片挤压

## 4. 详情与 Tooltip 规则

长文案必须进入详情层。

适合进入详情层：

```text
证据摘要
复核备注
原始信源链接
完整事件描述
同类客户补充说明
规则版本说明
```

详情层可以滚动，主表和卡片不允许因详情字段而撑爆。

tooltip 只用于轻量补充，不承载长段落。超过 80 字的内容进入详情面板。

## 5. 宽度与高度保护

1440×900 是基础验收视口。

验收失败条件：

- 字段互相覆盖或挤压
- 文字大量断裂
- 模块高度被单条内容撑爆
- 卡片内出现小字堆叠
- 主表出现横向滚动
- 单个模块因为内容过多破坏整体网格

可接受处理：

- 主表隐藏次要列
- 卡片减少展示行数
- 表格保留固定行高
- 详情面板承接完整内容
- tooltip 承接短补充

不可接受处理：

- 缩小字号硬塞
- 横向滚动主表
- 把所有字段并排放进一行
- 把详情字段放进首屏
- 通过扩大卡片高度解决信息过载

## 6. 模块优先级

首屏优先展示：

1. 标题与当前筛选上下文
2. KPI 或本周核心概览
3. 主列表/核心榜单
4. 关键趋势或结构图
5. 展会窗口或证据摘要入口

低优先级信息进入详情层：

```text
原始链接
完整证据链
审计记录
规则版本
复核备注
长解释
```

## 7. Agent 验收规则

内容 Agent 交付后，可视化 Agent 必须执行字段取舍。

如果内容层提供了短字段、长字段和证据链，而页面仍然挤压，判定为可视化层失败。

如果内容层只提供长段落、没有短字段、没有详情字段分离，则判定为内容层失败。

最终标准：

```text
不是谁写得多谁错，而是页面必须建立展示优先级。
内容可以完整，页面只能展示该展示的部分。
```
